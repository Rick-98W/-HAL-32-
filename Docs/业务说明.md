# 业务说明

本文描述当前工程（STM32F429，裸机主循环，由调度器轮询各任务）的业务流转、模块职责、函数写法，以及模块之间的调用关系。指令格式见 [串口指令集.md](串口指令集.md)。

---

## 1. 模块总览

| 模块 | 文件 | 职责 | 运行上下文 |
| :--- | :--- | :--- | :--- |
| 调度器 | `Components/scheduler.c` | 按周期轮询各任务 | 主循环 |
| 按键 | `Components/button_task.c` | ebtn 消抖，把点击转成菜单输入 | 主循环（`button_proc`） |
| 旋钮 | `Components/knob_task.c` | 读 ADC2 均值，死区滤波，变化时回调 | 主循环（`knob_proc`，20 ms） |
| 串口 | `Components/USART_task.c` | 接收环形缓冲、拆分指令、分发到各模块；发送环形缓冲 + DMA | 主循环 + DMA/HAL 回调 |
| 菜单 | `Components/menu/` | 菜单树、导航、值编辑、OLED 绘制入口 | 主循环 |
| DAC | `Components/DAC_service.c` | 波形 LUT、TIM6 定时、DMA 输出、变化回调 | 主循环 |
| ADC | `Components/ADC_service.c` | 采样窗口（DMA 环形缓冲）、TIM3 采样率、快照、代数 | 主循环 + DMA 回调 |
| 波形分析 | `Components/wavAnl_service.c` | 对快照调用分析库，缓存结果，判断结果是否过期 | 主循环 |
| 串口导出 | `Components/serial_export_task.c` | 通用逐行导出，不依赖任何数据源 | 主循环 |

| LED | `Components/LED_task.c` | 六路 LED 相位、黑屏 | 主循环（`LED_proc`，1 ms） |

## 2. 启动顺序

`Core/Src/main.c` 中 `MX_*_Init()` 之后，按以下顺序初始化业务模块：

```c
button_task_init();   // ebtn 注册按键
USART_init();         // 串口接收 DMA 启动
scheduler_init();     // 任务表长度
ICAP_init();
OLED_init();
OLED_page_init();
menu_init();          // 建菜单树，注册旋钮回调
DAC_init();           // 启动 DAC DMA 和 TIM6
ADC_init();           // 注册 DAC 变化回调，启动 ADC DMA 和 TIM3
MP_init();            // 内存池划分
```

顺序上的约束：

* `DAC_init()` 必须在 `ADC_init()` 之前。`DAC_register_change_cb()` 注册时会立即回放一次当前 ARR，ADC 据此设定 TIM3。
* `MP_init()` 必须在第一次 `MP_alloc()` 之前。分析和导出都依赖内存池。

## 3. 主循环与调度

```c
while (1) {
    scheduler_run();    // 按表轮询
    OLED_task_poll();   // OLED 每圈调用一次
}
```

`scheduler_run()` 的任务表（`Components/scheduler.c`）：

| 任务 | 周期 | 作用 |
| :--- | :--- | :--- |
| `LED_proc` | 1 ms | LED 相位输出 |
| `button_proc` | 5 ms | ebtn 处理，产生点击事件 |
| `USART_proc` | 1 ms | 报告发送丢弃，解析一条接收指令 |
| `serial_export_proc` | 1 ms | 导出一行 |
| `knob_proc` | 20 ms | 读旋钮，变化时回调 |

调度器只按 `HAL_GetTick()` 判断是否到期，每个任务在一圈里最多执行一次。

## 4. 输入路径

### 4.1 按键

```
EXTI 电平 → user_btn_read() → ebtn 消抖 → button_event_callback()
          → menu_handle_key(menu_input_t) → 按 menu_mode 分支
```

* 只处理 `EBTN_EVT_ONCLICK`（单击）。
* 按键映射：`KEY1`=上，`KEY2`=下，`KEY3`=确认/进入，`KEY4`=返回，`WKUP`=只在部分模式下用作退出。

### 4.2 旋钮

```
knob_proc() [20 ms] → knob_read_raw()（ADC2 均值 8 次）→ 死区
                   → 变化 → menu_on_knob_change(raw)
```

`menu_on_knob_change` 只在「值调整模式 且 正在编辑」时才映射到 `s_editValue` 并刷新 OLED。其它时候忽略旋钮。

### 4.3 串口

```
RX DMA (IDLE) → 环形缓冲 → USART_stream_load()（遇 ';' 或 '\n' 结束）
             → USART_parse_command() → LED / ADC / DAC / SYS 分发
```

* 分发函数只做字符串匹配和调用，不包含业务逻辑。
* 业务动作直接调用 DAC / ADC / LED 模块的公开函数。
* 需要刷新菜单时，调用 `menu_ADC_suppl.h` 里的 `*_menu_refresh_*()`，由它决定是否重绘。

输出走 `USART_printf()`：格式化到栈上 256 字节，放入发送环形缓冲，DMA 空闲时启动发送。发送完成回调里继续发下一段。

## 5. 菜单系统

### 5.1 菜单树

```
Main (MAIN_PAGE)
├── LED (LED_PAGE)
│   ├── LEDSave / LEDLoad / LEDBlackOut / LEDLightUp   （动作）
│   └── LEDToggle (LEDToggle)                         （进入 LED 翻转模式）
├── ADC (ADC_PAGE)
│   ├── DACSetFSR        值项 0~3300
│   ├── DACSetPeriod     值项 5~5400
│   ├── DACSetWave (DACSetWave)  子页
│   │   ├── sinusodial / triangular / sawtooth   （动作）
│   ├── ADCSetSamplFactor (ADCSetSamplFactor)  子页
│   │   ├── single / double                      （动作）
│   ├── ADCExport        动作：导出采样窗口
│   └── ADCWaveParam     动作：分析并进入参数页
├── System (SYS_PAGE)
└── Log (LOG_PAGE)       动作：进入日志模式
```

### 5.2 节点类型与页面 ID

每个 `menuItem_t` 有一个类型和一个 `page_ID`：

| 类型 | 进入后 | 典型例子 |
| :--- | :--- | :--- |
| `SUBMENU` | 成为当前页（`sp_currentPage`），光标落在第一个子项 | ADC、DACSetWave |
| `ACTION` | 执行回调，不改变页面 | sinusodial、ADCExport |
| `VALUE` | 进入值调整模式（`MENU_MODE_VALUE_ADJUST`），**页面不变** | DACSetFSR、DACSetPeriod |
| `TOGGLE` | 预留 | — |

`page_ID` 标识该节点对应的页面，用于区分界面（具体由 OLED 绘制代码使用）。它不等于「当前页」。`VALUE` 类节点的 `page_ID` 不会变成 `sp_currentPage`，所以判断某个值项是否可见，不能用 `page_ID`，要用 `menu_get_editing_item()` 或父页比较。

### 5.3 模式

`menu_mode_t`：

| 模式 | 进入方式 | 退出方式 |
| :--- | :--- | :--- |
| `MENU_MODE_NORMAL` | 默认 | — |
| `MENU_MODE_VALUE_ADJUST` | 在值项上按确认 | 返回键（未编辑时）退出 |
| `MENU_MODE_LED_TOGGLE` | LEDToggle 动作 | WKUP |
| `MENU_MODE_LOG` | Log 动作 | 返回键 |
| `MENU_MODE_WAVE_PARAM` | ADCWaveParam 动作 | 返回键 |

值调整模式内部还有一个 `s_valueEditing` 标志：

* 未编辑：显示 `*p_value`（模块缓存值）。确认键开始编辑，旋钮生效。
* 编辑中：显示 `s_editValue`。确认键写回 `*p_value` 并调用 `fn_value_adjust_callback`（即模块的 setter）；返回键取消。

### 5.4 光标与焦点

* `menu_navigate()`：上下键循环切换兄弟节点；确认键按节点类型分发；返回键回到父页。
* `menu_focus_item()`：把光标放到当前页的某个子项。用于进入子页的回调（如 `DAC_set_wave_enter`），以及菜单侧的刷新函数（如 `DAC_menu_refresh_waveType`），让光标落在与当前波形或采样倍率对应的项上。
* `menu_get_editing_item()`：只读，返回「正处于值调整模式的项」，否则 NULL。

### 5.5 OLED 刷新规则

OLED 是事件驱动的，没有固定帧率。绘制入口是 `OLED_proc()`，只有以下情况才调用它：

1. 菜单导航或模式切换（`menu_navigate`、`menu_return_normal_mode`、`menu_value_route`）。
2. 旋钮在编辑中产生新值（`menu_on_knob_change`）。
3. USART 改了模块值，并且这个值在屏幕上可见（见 6.3）。

## 6. 模块之间的调用关系

### 6.1 DAC 变化通知

DAC 是信号源，它的三个设置都可能改变输出：

| 调用 | 变化判断 | 通知 |
| :--- | :--- | :--- |
| `DAC_set_FSR(v)` | 夹紧后与当前值不同 | 是 |
| `DAC_set_period(v)` | 夹紧后与当前值不同 | 是（在 `DAC_restart_dma` 中，ARR 已更新） |
| `DAC_set_wave(t)` | 与当前波形不同 | 是（在 `DAC_restart_dma` 中） |

通知的内容是当前 `targetARR`，通过 `DAC_register_change_cb()` 注册的回调接收。

```
DAC_set_xxx() ──变化──> s_changeCb(ARR) ──> ADC_on_DAC_change(ARR)
                                              ├─ 保存 ARR
                                              ├─ 设置 TIM3（double 时除以 2）
                                              └─ ADC_reset_window()（代数 +1）
```

ADC 只调用 `DAC_register_change_cb()` 这一个 DAC 函数，不调用任何 DAC 的 getter。

### 6.2 ADC 窗口与采样

* ADC1 规则组的转换由 TIM3 的 TRGO 触发（见 `Core/Src/adc.c`），DMA 持续把结果写入 `s_ADCWaveWindow[1024]`，形成环形缓冲。
* 采样率 = TIM3 频率。`double` 时 ARR 减半，采样速度加倍。
* `ADC_is_window_ready()`：自上次复位以来写入的点数 ≥ 窗口长度（或已经写满过一圈）。
* `ADC_reset_window()`：停止 DMA，清除「已满」标志，代数加一，重新启动 DMA。
* `ADC_snapshot(dst, len)`：暂停 TIM3，按时间顺序拷贝最近 `len` 个点，恢复 TIM3。拷贝前后检查 DMA 写指针，若期间被覆盖则重试（最多 3 次）。**不重置窗口，不改变代数。**

### 6.3 波形分析与结果有效性

```
wavAnl_update()
  ├─ ADC_is_window_ready()           未满则返回
  ├─ MP_alloc(len * 2)               分配快照
  ├─ ADC_snapshot(snap, len)         拷贝
  ├─ wave_analyze(...)               分析库
  ├─ MP_free(snap)
  └─ 记录 s_resultGen = ADC_get_generation()
```

结果有效性：

```c
bool wavAnl_is_valid(void) {
    return s_has_result && s_resultGen == ADC_get_generation();
}
```

代数只在 ADC 窗口被重置时变化。DAC 的任何实际变化、以及 `ADC_set_ratio` 的实际变化都会重置窗口。因此只要代数不同，结果就一定是旧窗口算出来的，不会出现「参数 A→B→A 之后旧结果又被当成有效」的情况。

调用方：

| 调用方 | 行为 |
| :--- | :--- |
| 串口 `ADC get ...` | `ADC_ensure_wave_result()`：有效则直接用，无效则自动 `wavAnl_update()` |
| 串口 `ADC analyze` | 强制 `wavAnl_update()` |
| 菜单 ADCWaveParam | 进入前 `wavAnl_update()` |
| OLED 参数页 | 调 `wavAnl_menu_info()`，结果无效则显示「waiting for sampling...」 |

### 6.4 串口导出

分三层，依赖只向下：

```
应用层   menu_ADC_suppl.c : ADC_wave_export_start()
            │  快照 + 转换 mV + 持有快照
            ▼
通用层   serial_export_task.c : serial_export_start(src, ctx, count, done)
            │  每 1 ms 调用 src(ctx, idx) 输出一行
            ▼
输出     USART_printf()
```

生命周期：

1. `ADC_wave_export_start()` 检查导出是否忙、窗口是否已满。
2. `MP_alloc()` 申请快照，`ADC_snapshot()` 拷贝。
3. `serial_export_start(ADC_export_sample, snap, len, ADC_export_release)`。
4. 之后每 1 ms 输出一行，格式 `序号.: 值`。
5. 输出完成，调用 `done`，即 `ADC_export_release()`，释放快照。
6. 启动失败时，在启动函数里立即释放。

`serial_export` 不知道数据来自哪里，只要求 `src` 在导出期间有效。

### 6.5 内存

* 系统不使用堆。`MP_alloc()` 从 8 KB 的固定块池分配（类别：32 / 128 / 512 / 2048 字节）。
* 分析和导出的快照长度与窗口相同：double 时 1024 个 `uint16_t`（2048 字节），single 时 512 个（1024 字节）。两者都落在 2048 字节块类，各占一块。用完立即 `MP_free()`。
* 池子某一类用完时直接返回 NULL，不向其它类借块。调用方必须检查返回值。

## 7. 依赖关系图

```
main.c
 ├─ scheduler ─┬─ LED_proc
 │             ├─ button_proc ──> menu_handle_key ──┐
 │             ├─ USART_proc ──> USART_parse ──┬─> LED 模块
 │             │                               ├─> DAC 模块 ──(回调)──┐
 │             │                               ├─> ADC 模块 <─────────┘
 │             │                               │    ▲
 │             │                               │    │ wavAnl / ADC_snapshot
 │             │                               ├─> wavAnl ──────────────┘
 │             │                               └─> menu_ADC_suppl（刷新/导出适配）
 │             ├─ serial_export_proc
 │             └─ knob_proc ──> menu_on_knob_change
 └─ OLED_task_poll

menu ──> OLED_proc
menu_ADC_suppl ──> DAC / ADC / wavAnl / serial_export / memory_pool
serial_export ──> USART（只用 USART_printf）
DAC  ──> 无上层依赖（只通过回调通知）
ADC  ──> DAC 类型 + 回调注册（不调用 DAC getter）
wavAnl ──> ADC（快照、代数），分析库
```

依赖方向的原则：**底层不认识上层**。DAC 不知道 ADC 的存在；serial_export 不知道 ADC 的存在；ADC 只通过回调接收 DAC 的变化。

## 8. 函数写法约定

### 8.1 命名

* 模块公开函数：`模块前缀_动词_名词`，如 `DAC_set_FSR`、`ADC_snapshot`、`wavAnl_get_freq`。
* 只在本文件使用的函数：`static`。名字仍带模块前缀（如 `DAC_set_wave_enter`），与现有代码保持一致。
* 菜单回调：`static void 模块_动作(void)`，如 `DAC_set_sinusodial`。
* 串口分发：`static void 模块_dispatch_command(char *p_subCmd)`，只做匹配和调用。
* 宏：全大写，如 `ADC_WINDOW_SIZE`、`DAC_PERIOD_MAX`。
* 变量前缀：静态变量 `s_`，全局 `g_`，指针 `p_`，布尔 `b_`，常量 `k_`，枚举 `e_`。

### 8.2 头文件

* 每个模块一对 `.h/.c`，`.h` 只声明公开接口。
* 引用用 `#include <模块名.h>`。
* 需要 `typedef` 的类型（如 `e_waveType_t`）放在被使用方包含的头文件中，不要为了避免包含而重复声明。

### 8.3 回调

* 模块向上层通知变化时，用「注册 + 函数指针」，不要直接 `#include` 上层。例：`knob_register_change_cb`、`DAC_register_change_cb`。
* 注册函数允许在注册时立即回放一次当前值，避免接收方不知道初始状态。
* 回调参数只传基本类型（ARR、raw 值），不传模块内部结构。

### 8.4 只发事件，由菜单决定是否重绘

* 业务模块不直接调用 OLED。需要刷新屏幕时，调用菜单侧的 `*_menu_refresh_*()`。
* `*_menu_refresh_*()` 先更新菜单的缓存值（如 `s_DACFSRView`），再判断该值是否正在屏幕上可见，可见时才调用 `OLED_proc()`。缓存更新不受可见性影响，保证之后进入页面时显示的是新值。
* 判断「是否可见」用 `menu_get_editing_item()` 或父页比较，不用 `page_ID`（见 5.2）。

### 8.5 中断与主循环

* ISR 中只做标记（如 `s_wrapped = true`），标记声明为 `volatile`。
* 禁止在 ISR 中调用 `USART_printf`、`MP_alloc`、`HAL_Delay`。
* `USART_printf` 内部用临界区保护发送环形缓冲的写入。
* 当前所有 ADC / 导出 / 分析调用都在主循环上下文中执行，不需要额外的临界区。若将来有 ISR 或其它上下文要调用这些函数，需要重新评估。

### 8.6 错误与提示

* 每个分发分支最后都要有 `else` 分支，输出 `[WRN]`，列出该模块的合法子指令。
* 不能静默失败：拒绝执行时必须有回应（`[WRN]` / `[ERR]` / `waveform: ...`）。
* 结果不可用时（如窗口未满）给出原因，不返回旧值或零值。

## 9. 已知限制

| 项 | 现状 | 说明 |
| :--- | :--- | :--- |
| ADC 头文件包含 DAC | `ADC_service.c` 包含 `DAC_service.h` | 仅为注册回调与 `e_waveType_t`；如要完全解耦，可把注册挪到 `main.c` |
| 导出忙时静默 | `ADC wave export` 在导出进行中再次发送时无回应 | 可加 `[WRN]` |
| 自动分析失败只显示分析的错误 | `ADC get ...` 自动分析失败时，不打印结果行 | 符合当前设计 |
| SYS 模块 | 只回显 | 预留 |
| TX 丢数据 | 缓冲区满时丢字节，并打印一行 `[WRN]` | 正常情况下不会发生 |
| 外部信号源变化 | 无法立即识别 | 只能靠数据判断，当前未实现 |
| ADC 采样率跟随 DAC | 设计如此 | 若要接外部信号源，需要固定采样率并用测得频率换算 |
